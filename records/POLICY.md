# 后续版本的记录与预览约定

用户确认于2026-10-21。此文件记录项目长期工作方式，不表示存在无人值守的后台同步服务。

## 每次交付一起保存

- 发布和同版本修订：新增独立版本目录，保存改了什么、为什么改、实际源提交和前一个比较基线。相同版本多次修订使用独立目录，如v0.4.1-hotfix，不覆盖上一份记录。
- 纯分析：保存问题、代码版本、结论、证据、限制、实验配置和结果；没有修改代码就明确写出。新的分析放records/analyses，不能把后来的解释冒称为原始聊天逐字稿。
- 测试：保存真实命令、环境、原始输出、截图/数据、通过或失败及未验证项。历史版本不在新引擎下重跑后冒称旧结果；对照必须说明Seed、时间窗口、阈值和统计口径。
- 原始数据、失败结果和数值中断一起保存，不只收集成功示例。区分研究数据和实施后的验收数据。
- 当前源码、分析和记录在同一次交付中推送GitHub；未完成或无法取得的证据标记缺失，不编造。

## 目录及工具

records/versions/<版本或修订>/README.md 是每次交付的阅读入口，snapshot保留当时新增/改动的说明、测试代码、输出和截图；changes.patch保留实现差异，record.json记录来源与SHA256。未变化的证据沿前一版查阅，Git原始提交仍可用于完整还原代码。

先提交实际代码/实验，再捕获该源提交，最后将新增记录一同提交、推送：

```sh
python tools/records.py capture --id v0.5.3 --ref HEAD --previous <前版源码提交> --title "本次改动标题" --summary "原因、改动、验证与限制"
# 同版本修订使用新ID，例如v0.5.3-hotfix-1；已有目录拒绝覆盖。
# 纯分析用 --kind analysis --id <分析主题>，ref指向包含实际报告/数据的提交。
python tools/records.py check
```

capture直接读取Git对象，不复制未提交文件。自动更新总目录和index.json；check核验每份证据的大小、哈希、目录完整性、当前版本和实际运行源码是否已归档。GitHub记录检查工作流执行同样检查，帮助发现“只改源码、没补记录”。Python工具只依赖标准库。

不可为了使检查通过而覆盖旧记录或改写历史源提交。若记录勘误，新增修订说明/记录并指出原问题；原始实验结果仍保留。

## GitHub与私有网页各自负责什么

- GitHub用于源码、版本、分析、测试、离线包和协作访问；之后版本不再默认使用GitHub Pages作为预览入口。
- 默认查看方式沿用原私有网页： https://trisolaris-reconstruction-20261019.wittylark8.chatgpt.site/ 。发布版本需要预览时更新已有站点，不默认另建网址。
- Pages工作流仅保留手动触发；推送main不再自动部署。GitHub构建/测试不等于私有网页已经更新。
- 在已有独立分支验收约定下继续工作，不自动合并main。除非用户另有明确要求，不变更站点访问权限或把私有预览改成公开发布。
- 本次归档没有更新私有站点代码，也没有更改站点访问权限；当前网页实际版本须以站点本身显示为准。后续交付分别说明GitHub提交和私有预览状态。
