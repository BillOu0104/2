## 3. 文明韧性、等级与死亡是怎样算的

环境适宜度反映当前温度和潮汐，不等于文明还剩多少生命。文明没诞生前，人口、干仓质量、韧性和等级显示为“—”，不会被几百年的严寒提前扣光。短暂但连续安全的窗口满足 birthDelay 后才建立新文明，两个储备从100%开始。

文明具有两种归一化储备，百分比不是虚构的精确人口普查：人口储备表示可延续的人口，干仓质量表示脱水生命和保存体系的完好程度。综合韧性=人口储备×干仓质量。安全且处于活动状态时，两者每模拟秒分别恢复1.5和1个百分点，最高100%。脱水储存范围以内不凭时间强制扣寿命；超出干仓耐受范围才持续损失保存质量，同时以较慢速度损失人口。已恢复的旧结构损伤不会继续作为固定伤害源。

保护分母=thermalGrace×等级韧性倍率。休眠气候损耗率=(0.015+超出干仓温度范围的摄氏度/2000)/保护分母；没有越界时为0。人口承受此损耗的15%。尚未脱水的异常气候人口损耗=(0.05+超出活动温区的度数/300)/保护分母。当前有效潮汐应力超过1时另有结构损耗；不是一有“飞星”就杀死文明。任一储备降至1%或以下，文明终结。恒星吞噬、行星完整度归零则立即结束文明；高级文明也没有免疫这些事件。

阶段流程：安全生产 → 不适宜时脱水（1秒）→ 干仓保存 → 连续安全 wakeDelay 秒 → 浸泡（0.5秒）→ 恢复同一文明。浸泡中环境再次不安全，回干仓；编号与等级保留。文明终结后再遇安全窗口才产生新编号，科技从头开始。

发展年数只在文明确实处于“恢复生产/发展”、温度合适且行星安全时积累，再乘 developmentRate。**文明寿命包含休眠，科技发展年数不包含休眠。** 如果改动基础温区，表中所有等级范围会随之平移/扩展。文明阶段参考原著展示的农业、工业、原子信息及远航发展方向；200/800/1800/3500/6000/9000/12000/16000/21000/28000/40000生产年阈值与保护倍率都是本版本的设计，并非小说给定数值；没有假装已经实现智子制造或真实星际迁移。

恒/乱纪元独立按轨道束缚与扰动判断。乱纪元可有短暂适温窗口，寒冷恒纪元也不一定适合生产。V2不会因行星毁灭重置三星，而是等待至少5显示年后按P5生成新行星；原文明的死亡保留，新文明从头发展。旧版现代模式不会只因“飞得远”“文明死亡”或“气温极端”自动开新宇宙；v0.5.4额外在未开启牢笼且保守逃逸条件持续3显示年时重建，不改变实际引力或轨道。设置→文明档案→完全重置历史可清除宇宙/文明档案、排行榜和累计年份，保留设置和背景；普通重启与恢复默认仍保留历史。

日志只保留最近12个事件、屏幕最多6行：文明启动、毁灭、每50年寿命里程碑、等级晋升，以及确认超过0.5秒的三日连珠/三日凌空/飞星不动，同类天象冷却60模拟秒。常规飞星、脱水切换等不逐条刷屏。

## 4. 每个控件的完整参考

“默认”指v0.6.1新安装值；本次不改变v0.6.0的默认物理值或已保存设置。V2保护默认开启，固定最大步长0.0001875、η0.001875、每60帧1显示年；播放速度只增加完整模拟帧数，不跳过积分。旧配置首次升级默认选择V2，显式off配置保留旧版；旧Seed档案缺少模式时按旧版重放。银河归位旧默认0.003迁移为0.006°/秒（更早默认0.01同样迁移），自定义速度保留。v0.5.2 默认 research 初始化、newtonian 引力、牢笼关闭；旧配置升级会切换这些默认项。相同 Seed 的轨迹已改变，要复现 v0.5.1 必须显式选择 chaotic + legacy 并恢复旧牢笼与其余参数。升级时原有自定义值保留；仅识别到旧默认 k2=0.22、thermalGrace=8、wakeDelay=3 时迁移为0.30、30、1。v0.5.1还把旧默认epochWindow=2迁移为1/12模拟年；其他明确自定义值保留数值，按模拟年解释，并记录epochTimebase=years。已保存的灵敏度、窗口位置、背景、音量和档案继续保留。表内“兼容保留/不生效”项如实列出，避免误以为滑块必定改变现代逻辑。

## 5. 修改如何生效、如何备份

界面改动会立即保存，传给渲染器与Worker。画面、布局、视角、音量和科技倍率不重建轨道。Seed、初始化模式、物理时钟或积分步长会重建物理模块；原版映射的质量、初值、软化、牢笼和时间倍率也可能触发原版物理初始化。因此建议先导出种子，再调大范围物理参数，最后用“重启”明确开始一次新宇宙；不要在同一段观测中频繁改变物理设置后比较榜单。改变韧性、温区与科技倍率是即时作用，不恢复已经损失的人口，也不复活已经终结的文明。

修改默认值不会覆盖所有用户保存值。默认常量在 src/settings.js 的 defaults / extraDefaults；控件分类与显示名在 src/settings-layout.js，悬停解释在 src/settings-descriptions.js，范围在 src/settings-catalog.js（扩展）与 src/original-data.js（原版）；合法范围还需同步 normalizeSettings。升级旧默认须在 migrateSettings 添加一次迁移；presentationRevision 当前为6；银河归位的默认值迁移单独使用galaxyReturnRevision=2。直接随意增加此号可能触发现有迁移，应明确旧值与保留策略。

导出种子包含完整配置、算法标识与四体初始坐标。导入会重新初始化，不是继续之前的位置。物理算法、气候与文明规则版本不同，旧种子的文明结果不能保证完全一致。手动初值范围受原版属性表限制。档案的“复现初始种子”重放初始条件，不提供整段历史回滚。

可通过控制台试调并由正常接口持久保存：

```js
window.threeBody.applySettings({
  thermalGrace: 40,          // 更强的基础耐受
  developmentRate: 2,        // 两倍科技积累，寿命读数不翻倍
  viewSensitivity: 0.08,     // 整体鼠标倍率
  dragSensitivity: 3,        // 只调拖动
  compassOpacity: 0.08,      // 环8%不透明
  layout: { left: {x: 8, y: 45}, clock: {x: 50, y: 10} }
});
```

layout作为一个对象整体传入会替换旧的自定义坐标；界面单个滑块与拖动编辑器会自动合并其他窗口的坐标。所有位置都可能由layout.js做防越界处理，不必改CSS。想恢复默认布局用“恢复默认布局”；想恢复全部配置用面板底部“恢复默认”，文明档案仍保留。

Wallpaper Engine Web壁纸通过 wallpaperPropertyListener 接收原183个属性、暂停与音频；新增扩展项使用网页右下角面板，其中控制方案和播放速度也加入WE宿主属性；其他扩展项使用网页面板。离线包解压后选择 project.json / index.html。网页版通过HTTP运行；实际WE本地文件宿主需在Windows环境验收。

## 7. 已知模型边界

这是以原版算法和用户提供的原著讲解为基础的可调壁纸模拟，科技/人口为新增抽象模型。引力牢笼是额外力；提高k2只是有限时间内增加拉回，不保证永久不抛射。旧分段引力仅在legacy兼容模式保留；默认牛顿力与近遇自适应Yoshida来自v0.5.2。v0.5.5固定每个宇宙的初始质心显示原点，不跟随当前质心或星群。初始总动量非零的自定义配置会真实平移，不会暗中清零；真实弹射仍可能发生。温度有原版距离倍率与简化辐射模型，不是完整气候模型。长寿文明可能多数时间在干仓，而不是持续百年恒纪元；左侧实际发展年数用于区分。
