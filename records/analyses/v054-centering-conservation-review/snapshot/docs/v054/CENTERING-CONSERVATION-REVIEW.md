# 为什么此前采用星群跟随，而没有完成针对性守恒排查

日期：2026-10-21。分析对象：v0.5.4，Git提交 `a88fb6153c2a764078e299114eff781b41208dfd`；同时复核v0.5.3的修改说明和已有测试记录。本次只做静态阅读，运行模拟次数为0，不修改运行源码、不重新发布网页。

## 对此前处理的复核

用户此前澄清“能量守恒表现为天体离开中心显示位置”。v0.5.3把这个描述优先解释为显示中心不适合观测剩余星群，并加入星群跟随。这是当时实际采用的理由，见docs/v053/RELEASE.md开头。

该理由可以解释一部分视觉现象，但不足以排除初始化、动量守恒、积分误差或状态同步的问题。镜头跟随只处理画面，不能代替针对症状的物理检查。当时应先明确全体四体总质心是否在固定惯性坐标中漂移，再决定是否需要另外的镜头功能；这个排查顺序处理不当。

## 总质心与星群中心

质量不变、无外力、初始总动量为零时，全体四体的总质心速度应保持为零；若其初始位置也是原点，总质心应一直在原点附近，仅有数值舍入误差。这主要是动量守恒与质心运动定理，不是单独的能量守恒结论。

但总质心固定不要求剩余双星或三星的中心固定。一颗恒星获得向外动量时，剩余天体可以反向后退，正负动量抵消，总质心仍固定。逃逸可以永久发生；四体也可能留下更紧密的双星，同时有恒星和行星逃逸。守恒定律本身不要求“至多一颗暂时离开”。是否在本项目的具体画面中发生了这种物理解体，本次没有运行轨迹验证，不能据此直接认定。

## 本次读到的证据

- `src/orbital-initialization.js`中research默认初值最后调用`recenter(bodies)`，对四体质量加权位置和速度同时减去平均值，意图使总质心位于原点、总动量为零。该结论限于此初始化路径，不代表手动、original或兼容模式也保证相同条件。
- `src/physics/gravity.js`按天体对更新等大反向动量，并提供能量、总动量、角动量诊断。这是设计与代码结构证据，不能单靠阅读证明任意长时间近遇都数值可靠。
- `src/renderer.js`在绘制时先将各天体位置减去当前四体物理质心。开启`centerOnSystem`后又加入`displayCenter`提供的观察偏移。后者一般取恒星质心，间距明显分化时取最近恒星对的质心，见`src/display-center.js`。因此屏幕中的星群移动不能直接判断物理总质心是否漂移；跟随也会掩盖这种视觉症状。
- `docs/v053/results/physical-parity.json`比较v0.5.3与v0.5.2的八个预定Seed，各200显示年，证明轨道及守恒诊断逐位一致。v0.5.4采用类似一致性检查。它们证明相关改动没有改变轨道，**不证明共同基线绝无守恒缺陷**。不能将这些测试用作排除用户当前问题的充分依据。
- 启用引力牢笼时不满足孤立系统无外力前提；手动初值可能自带总动量；自动宇宙重建还会切换初态。核查时必须区分这些路径，不能将重置前后数值拼成同一条守恒曲线。

## 尚未作出的判断

本次没有新模拟、没有新守恒误差数字，也没有证明此次异常一定是真实弹射或一定是能量错误。正确的直接检查应针对发生异常的同一宇宙，在不重置、不使用牢笼的条件下，记录固定惯性原点下的四体总质心位置/速度、总动量、能量与近遇/接触状态，再区分整体质心漂移、真实反冲分离和显示变换问题。本次不擅自扩展为该模拟任务。

结论：此前添加跟随是为了保持星群可见，但不能视为守恒问题已解决；应该先检查动力学，再决定观察方式。记录与分析上传GitHub，私有网页保持v0.5.4不重新部署。
